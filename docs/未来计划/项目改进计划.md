## 一、安全性改进

### 1.1 密码 Hash 升级为 bcrypt（P0）

**问题**：当前使用 SHA256，不是密码专用算法，容易被彩虹表攻击。

**当前代码**：`tools/user_auth.py` 第 96-98 行

```python
# 当前
def _hash_password(self, password: str) -> str:
    return hashlib.sha256(password.encode()).hexdigest()
```

**改为**：

```python
import bcrypt

def _hash_password(self, password: str) -> str:
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt()).decode()

def verify_password(self, password: str, hash: str) -> bool:
    return bcrypt.checkpw(password.encode(), hash.encode())
```

**注意**：改动后需要迁移已有用户密码。建议保留 SHA256 验证作为 fallback，用户下次登录时自动迁移到 bcrypt。

**验收标准**：
- 新用户密码用 bcrypt 存储
- 旧用户登录时自动迁移，无需重置密码
- 添加 bcrypt 到 requirements.txt

### 1.2 API Rate Limiting（P1）

**问题**：当前无请求频率限制，存在被刷接口风险。

**方案 A：Nginx 层限流（推荐）**

```nginx
# deploy/nginx/default.conf

# 定义限流区域
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;
limit_req_zone $binary_remote_addr zone=chat_limit:10m rate=2r/s;

# 普通接口
location /api/ {
    limit_req zone=api_limit burst=20 nodelay;
    proxy_pass http://backend;
}

# 聊天接口（更严格）
location /api/v1/chat/stream {
    limit_req zone=chat_limit burst=5 nodelay;
    proxy_pass http://backend;
}
```

**方案 B：FastAPI 中间件限流**

```python
# backend/app/core/rate_limit.py
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)

# 在路由上使用
@router.post("/chat/stream")
@limiter.limit("2/second")
async def chat_stream(request: Request, ...):
    ...
```

**验收标准**：
- 单 IP 每秒最多 10 次普通 API 请求
- 单 IP 每秒最多 2 次聊天请求
- 超限返回 429 Too Many Requests

## 二、性能改进

### 2.1 Embedding 模型单例缓存（P2）

**问题**：`QdrantDB.__init__` 每次创建实例都重新加载 embedding 模型，耗时几秒且重复占内存。

**当前代码**：`tools/qdrant.py` 第 88-93 行

```python
# 当前
def __init__(self, input: QdrantDB_Init):
    from backend.app.core.model_runtime import backend_embedding_model
    self.embedding_instance = backend_embedding_model()  # 每次加载
```

**改为**：

```python
# backend/app/dependencies.py
from functools import lru_cache

@lru_cache(maxsize=1)
def get_embedding_model():
    from backend.app.core.model_runtime import backend_embedding_model
    return backend_embedding_model()

# tools/qdrant.py
def __init__(self, input: QdrantDB_Init):
    from backend.app.dependencies import get_embedding_model
    self.embedding_instance = get_embedding_model()
```

**验收标准**：
- 模型只加载一次
- 多次创建 QdrantDB 不重复加载
- 内存占用不增长

---

### 2.2 词汇索引异步预热（P2）

**问题**：首次搜索时 `_maybe_build_lex_index` 需要 scroll 全量数据，数据量大时阻塞请求。

**当前代码**：`tools/qdrant.py` 第 520-604 行

**建议**：启动时后台预热，不阻塞请求：

```python
# backend/app/main.py
@app.on_event("startup")
async def startup_warmup():
    import asyncio
    
    async def warmup():
        from app.dependencies import get_database_toolkit
        toolkit = get_database_toolkit()
        toolkit.warmup_lexical_index()
        logger.info("词汇索引预热完成")
    
    asyncio.create_task(warmup())
```

**验收标准**：
- 启动时自动预热词汇索引
- 预热期间请求不阻塞（可降级为纯向量检索）
- 预热完成后自动切换为混合检索

### 2.3 DatabaseToolkit 单例共享（P2）

**问题**：当前 `DatabaseToolkit` 可能在多处创建实例，每次都新建 `QdrantDB` 连接。

**建议**：在 `dependencies.py` 中统一管理单例：

```python
# backend/app/dependencies.py
_database_toolkit = None

def get_database_toolkit():
    global _database_toolkit
    if _database_toolkit is None:
        from tools import DatabaseToolkit
        _database_toolkit = DatabaseToolkit()
    return _database_toolkit
```

**验收标准**：
- 全局只有一个 DatabaseToolkit 实例
- QdrantDB 连接复用
- 词汇索引只构建一次

## 三、运维改进

### 3.1 健康检查增强（P1）

**问题**：当前 `/health` 只返回 200 OK，缺少详细信息。

**建议**：

```python
# backend/app/api/v1/health.py
from fastapi import APIRouter

router = APIRouter()

@router.get("/health")
async def health_check():
    checks = {}
    
    # Qdrant 连接检查
    try:
        from app.dependencies import get_database_toolkit
        toolkit = get_database_toolkit()
        point_count = toolkit.db._get_collection_point_count()
        checks["qdrant"] = {"status": "ok", "points": point_count}
    except Exception as e:
        checks["qdrant"] = {"status": "error", "message": str(e)}
    
    # Redis 连接检查
    try:
        from app.core.redis_client import get_redis_client
        client = get_redis_client()
        client.ping()
        checks["redis"] = {"status": "ok"}
    except Exception as e:
        checks["redis"] = {"status": "error", "message": str(e)}
    
    # 模型加载检查
    checks["models"] = {
        "embedding": "loaded" if embedding_loaded else "not_loaded",
        "reranker": "loaded" if reranker_loaded else "not_loaded",
    }
    
    overall = "ok" if all(
        v.get("status") == "ok" for v in checks.values() 
        if isinstance(v, dict) and "status" in v
    ) else "degraded"
    
    return {
        "status": overall,
        "version": "1.0.0",
        "checks": checks,
    }
```

**验收标准**：
- `/health` 返回各组件状态
- Qdrant 故障时返回 degraded 但不报 500
- 包含版本号、向量数等关键信息

### 3.2 Prometheus 监控指标（P2）

**建议添加的关键指标**：

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `rag_search_latency_seconds` | Histogram | mode=hybrid/vector/keyword | 检索耗时 |
| `rag_rerank_latency_seconds` | Histogram | - | 重排序耗时 |
| `rag_llm_latency_seconds` | Histogram | model=xxx | LLM 调用耗时 |
| `rag_llm_tokens_total` | Counter | model, type=input/output | Token 消耗 |
| `rag_sessions_active` | Gauge | - | 活跃会话数 |
| `rag_queries_total` | Counter | - | 总查询数 |
| `rag_ingested_files_total` | Counter | - | 入库文件数 |

**集成示例**：

```python
# backend/app/core/metrics.py
from prometheus_client import Counter, Histogram, Gauge, generate_latest
from fastapi import Response

SEARCH_LATENCY = Histogram(
    'rag_search_latency_seconds',
    'Search latency in seconds',
    ['mode'],
    buckets=[0.1, 0.5, 1.0, 2.0, 5.0, 10.0]
)

LLM_TOKENS = Counter(
    'rag_llm_tokens_total',
    'LLM tokens consumed',
    ['model', 'type']
)

ACTIVE_SESSIONS = Gauge(
    'rag_active_sessions',
    'Active chat sessions'
)

# 暴露指标端点
@app.get("/metrics")
async def metrics():
    return Response(
        generate_latest(),
        media_type="text/plain"
    )
```

**在检索工具中使用**：

```python
# tools/database_toolkit.py
import time

def _search_database(self, query, ...):
    start = time.time()
    
    if use_hybrid:
        hits = self.db.hybrid_search(...)
        SEARCH_LATENCY.labels(mode="hybrid").observe(time.time() - start)
    else:
        hits = self.db.search(...)
        SEARCH_LATENCY.labels(mode="vector").observe(time.time() - start)
```

**验收标准**：
- `/metrics` 端点可访问
- Grafana 可导入 Dashboard 展示指标
- 支持 P50/P95/P99 延迟统计

### 3.3 日志级别整理（P3）

**问题**：当前部分详细搜索过程用 `logger.info` / `_log_search` 输出，日志量大。

**建议**：

| 级别 | 使用场景 | 示例 |
|------|----------|------|
| `logger.error` | 需要立即处理的错误 | Qdrant 连接断开、模型加载失败 |
| `logger.warning` | 可自动恢复的问题 | Rerank 失败 fallback、Redis 不可用降级 |
| `logger.info` | 关键业务事件 | 搜索完成、文件入库、会话创建 |
| `logger.debug` | 详细过程信息 | query 改写详情、候选结果数、分数细节 |

**改动点**：

```python
# tools/database_toolkit.py
# 当前：详细搜索过程用 _log_search（print + logger.info）
# 改为：

logger.info(f"搜索完成: query='{query}', 结果={len(hits)}条")
logger.debug(f"搜索详情: candidates={len(all_hits)}, reranked={len(hits)}")
logger.debug(f"  query改写: '{query}' -> intent='{intent_description}'")

# 移除 _log_search 函数中的 print
```

**验收标准**：
- 生产环境（DEBUG=false）日志量减少 80%
- 关键事件仍然可见
- 调试时可开启 DEBUG 级别查看详情

## 四、用户体验改进

### 4.1 错误信息友好化（P3）

**问题**：部分错误信息暴露技术细节，用户不易理解。

**当前**：

```python
return "No results from the vector database."
return "知识库检索在本轮执行失败。"
return "抱歉，我无法生成回复。"
```

**建议**：

```python
# 用户可见的友好消息
USER_FACING_MESSAGES = {
    "no_results": "抱歉，在当前知识库中没有找到与您问题相关的信息。请尝试换个方式描述您的问题。",
    "search_failed": "抱歉，知识库检索遇到了临时问题，请稍后重试。",
    "llm_error": "抱歉，回答生成遇到了问题，请稍后重试。",
    "token_limit": "当前对话过长，建议开启新对话继续提问。",
}

# 内部日志保持详细
logger.warning(f"Search failed for query='{query}': {exc}")
```

**验收标准**：
- 用户看到的所有错误消息不含技术术语
- 内部日志保留完整错误堆栈
- 错误消息提示用户下一步操作

### 4.2 文件上传进度反馈（P3）

**问题**：大文件上传入库时用户无法感知进度。

**建议**：
- 前端显示上传进度条
- 后端返回入库阶段状态（解析中 → 切块中 → 入库中 → 完成）

```python
# backend/app/api/v1/files.py
@router.post("/import")
async def import_file(...):
    # 返回任务 ID
    task_id = str(uuid.uuid4())
    
    # 后台执行入库
    background_tasks.add_task(
        ingest_file_with_progress,
        task_id=task_id,
        file_path=file_path
    )
    
    return {"task_id": task_id, "status": "processing"}

@router.get("/import/{task_id}/status")
async def get_import_status(task_id: str):
    # 从 Redis 查询入库进度
    status = redis.get(f"import:{task_id}")
    return json.loads(status)
```

**验收标准**：
- 上传后前端可轮询入库进度
- 进度包含：解析、切块、入库、完成
- 入库失败时返回具体原因
