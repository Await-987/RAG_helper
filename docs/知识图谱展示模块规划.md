# 知识图谱展示模块规划

## 目标

构建一个独立的知识图谱展示模块，用于项目演示。不接入主问答流程，仅展示从电网设计规范中抽取的实体-关系-实体三元组，以力导向图的形式可视化呈现。

---

## 整体架构

```
Qdrant 已有 chunks
       │
       ▼
[抽取脚本] ──LLM批量抽取──▶ knowledge_graph.json
                                    │
                                    ▼
                         [后端 API /api/knowledge-graph]
                                    │
                                    ▼
                         [前端 图谱可视化页面]
```

---

## 模块一：三元组抽取脚本

**文件**: `tools/kg_extractor.py`

### 功能

1. 从 Qdrant 中 scroll 读取所有 chunks（或指定文件的 chunks）
2. 每 3-5 个 chunks 为一批，拼接后发送给 LLM
3. LLM 按 prompt 返回结构化三元组
4. 去重、合并同义实体，输出最终 JSON

### 抽取 Prompt 设计

```
你是一个电力工程知识图谱构建专家。请从以下电网设计规范文本中抽取实体和关系三元组。

实体类型：设备、规范标准、参数指标、设计要求、工程场景、材料
关系类型：适用于、要求满足、参数值为、引用规范、包含、连接、属于

请严格按以下 JSON 格式输出：
{
  "triples": [
    {"head": "实体1", "head_type": "类型", "relation": "关系", "tail": "实体2", "tail_type": "类型"}
  ]
}

文本内容：
{chunk_text}
```

### 输出格式

文件路径: `data/knowledge_graph/{collection_name}_kg.json`

```json
{
  "meta": {
    "collection": "xxx",
    "extracted_at": "2026-05-20T12:00:00",
    "total_chunks_processed": 500,
    "total_nodes": 320,
    "total_edges": 580
  },
  "nodes": [
    {"id": "10kV配电线路", "type": "设备", "freq": 15},
    {"id": "GB 50229", "type": "规范标准", "freq": 8},
    {"id": "接地电阻≤4Ω", "type": "参数指标", "freq": 3}
  ],
  "edges": [
    {"source": "10kV配电线路", "target": "GB 50229", "relation": "引用规范", "weight": 3},
    {"source": "接地装置", "target": "接地电阻≤4Ω", "relation": "要求满足", "weight": 2}
  ]
}
```

### 实体去重策略

- 完全相同的字符串直接合并
- 用 LLM 做一轮同义词合并（如"变压器"和"变压器设备"）
- `freq` 字段记录该实体被提及的次数，用于前端节点大小映射

## 模块二：后端 API

**文件**: `backend/app/api/knowledge_graph.py`

### 接口设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/knowledge-graph` | 返回完整图谱 JSON |
| GET | `/api/knowledge-graph/stats` | 返回节点/边统计信息 |
| GET | `/api/knowledge-graph/subgraph?node=xxx&depth=2` | 返回某节点的 N 跳子图 |

### 实现要点

- 直接读取 JSON 文件，无需数据库
- 加内存缓存（文件修改时间不变则不重新读取）
- subgraph 接口用 BFS 从指定节点出发，返回 depth 跳内的所有节点和边

## 模块三：前端图谱可视化页面

**文件**: `frontend/src/pages/KnowledgeGraphPage.tsx`

### 技术选型

使用 `@antv/g6`（v5），理由：
- 蚂蚁出品，中文文档完善，社区活跃
- 力导向布局开箱即用，支持大量节点（1000+）
- 内置缩放、拖拽、框选、tooltip
- 支持节点/边自定义样式，展示效果专业

备选：`react-force-graph-2d`（更轻量但定制性差）

### 页面布局

```
┌─────────────────────────────────────────────────┐
│  侧边栏  │          知识图谱可视化                │
│          │  ┌─────────────────────────────────┐  │
│  [图谱]  │  │  [统计卡片: 节点数 | 边数 | 类型] │  │
│          │  ├─────────────────────────────────┤  │
│          │  │                                 │  │
│          │  │        力导向图区域              │  │
│          │  │     (全屏可交互)                 │  │
│          │  │                                 │  │
│          │  ├─────────────────────────────────┤  │
│          │  │  [筛选栏: 实体类型 | 关系类型]    │  │
│          │  │  [搜索框: 搜索实体名称]          │  │
│          │  └─────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

### 交互功能

1. **节点着色** — 按实体类型分色：
   - 设备 → 蓝色
   - 规范标准 → 绿色
   - 参数指标 → 橙色
   - 设计要求 → 紫色
   - 工程场景 → 青色
   - 材料 → 红色

2. **节点大小** — 按 `freq`（被提及次数）映射，高频实体节点更大

3. **边标注** — 边上显示关系名称，hover 时高亮

4. **点击交互**：
   - 点击节点 → 高亮该节点及其所有直接关联节点和边，其余变灰
   - 双击节点 → 以该节点为中心展开子图（调用 subgraph 接口）
   - 点击空白 → 恢复全图

5. **筛选功能**：
   - 按实体类型筛选（多选 checkbox）
   - 按关系类型筛选
   - 搜索框模糊匹配实体名称，定位并高亮

6. **图例** — 右下角显示颜色-类型对应关系

### 路由

在 Sidebar 中新增"知识图谱"入口，路由 `/knowledge-graph`

## 模块四：抽取脚本执行流程

### 运行方式

```bash
# 在 backend 容器内执行
python -m tools.kg_extractor --collection default_collection --batch-size 5 --output data/knowledge_graph/
```

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| --collection | default_collection | Qdrant collection 名称 |
| --batch-size | 5 | 每批发送给 LLM 的 chunk 数 |
| --max-chunks | 500 | 最多处理的 chunk 数（控制成本） |
| --output | data/knowledge_graph/ | 输出目录 |
| --model | 配置文件中的模型 | 使用的 LLM 模型 |

### 执行步骤

1. 连接 Qdrant，scroll 获取 chunks（按文件分组，优先取不同文件的内容以增加多样性）
2. 每 batch-size 个 chunks 拼接，调用 LLM 抽取三元组
3. 收集所有三元组，执行去重：
   - 精确去重：(head, relation, tail) 完全相同的合并，weight +1
   - 实体归一化：去除空格、统一全半角、"XX设备"→"XX"
4. 构建 nodes 列表（从所有三元组的 head/tail 中提取唯一实体）
5. 计算 freq（每个实体作为 head 或 tail 出现的次数）
6. 输出 JSON 文件

### 成本估算

- 假设 500 chunks，每 5 个一批 = 100 次 LLM 调用
- 每次输入约 2000 tokens，输出约 500 tokens
- 总计约 25 万 tokens，使用本地模型无额外成本

## 展示效果预期

演示时可展示：
1. 全局图谱总览 — 展示规范文档中抽取出的实体关系网络
2. 点击某个核心设备节点（如"变压器"）— 展开其关联的规范、参数、设计要求
3. 按类型筛选 — 只看"设备-规范"关系，或只看"参数指标"相关节点
4. 搜索定位 — 输入关键词快速定位到相关实体

这些交互足以展示"从规范中自动抽取知识图谱"的能力，体现项目在知识图谱构建方面的研究成果。
